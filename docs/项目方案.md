# 个人英语教练：统一项目方案 v1.0

日期：2026-10-04。状态：设计阶段。本文完整替代以前方案，是当前唯一有效需求，不再保留互相冲突的历史阶段要求。

## 1. 产品定位与目标

为一位中国职场新人打造漂亮、温暖、有学习宠物陪伴的私人英语空间。用户从事采购数字化、AI Agent 和项目管理，目标为职场沟通、雅思备考与英语日常表达。

核心闭环：打开漂亮界面 → 选择任务或讲述心情 → 语音/文字表达 → 温柔而准确的反馈 → 再次表达 → 自动写入 Obsidian → 后续复习。

产品提供真实可用的视觉界面；Codex 用于开发、维护及可选对话入口。不能把展示原型称为可用应用，也不能假设 HTML 自动拥有 Codex 的对话、语音或文件权限。

## 3. 界面与运行形式

### 推荐路线

采用响应式 Web 界面，电脑和手机共用设计；先实现本地可用版本，提供简单启动方式，再根据手机验证选择安全的远程访问。允许后续加入 PWA，安装能力与浏览器限制需实测。

首版先按轮录音，确保录音、纠错和归档可恢复；实时对话是后续增强。微信小程序作为未来分发形式，不作为第一版必需交付。

存在两种运行方案，需在早期做一个最小验证后选择，不能混称：

| 方案 | 特点 | 限制与决策 |
|---|---|---|
| 独立界面 + 本地后端 + AI 服务 | 可完整控制输入、音频、宠物与归档 | 需可用 AI/语音服务和凭据；推荐产品路线 |
| 宿主支持的 HTML/MCP UI + Codex 教练 | 可复用宿主工具与对话 | 界面消息桥接、手机入口和音频访问必须验证；仅验证通过才采用 |

Codex 本身可继续作为备用练习入口，与界面使用相同 Vault 和会话 ID。手机 ChatGPT 语音是用户偏好的入口，单独验证 Remote 与本地保存；若不能共享完整记录，明确说明并优先使用应用录音入口，不能声称普通手机语音已自动同步。

普通静态 HTML 仅能演示交互，Figma 只负责设计，都不会自动提供教练或保存功能。不会把 AI 密钥放入浏览器代码。

## 4. 视觉设计与宠物

### 风格方向

默认方向为温暖、精致、安静的书桌：奶油白背景、低饱和鼠尾草绿、少量杏色点缀，清晰文字与柔和阴影。使用可读字号、足够对比度、轻动画；支持减少动态效果。避免密集面板和满屏红色纠错。

宠物暂定为原创圆润小猫，可改名与换造型。它是应用内角色，不等同于 ChatGPT Work Pets；当前不调用 Work Pets 工具。先用轻量矢量/动画实现，后续需要精细位图时再制作素材。

宠物状态：待机、问候、倾听、思考、鼓励、庆祝、安静陪伴。状态由实际产品事件驱动，麦克风是否录音有独立明确标识，不能靠宠物表情表示。默认不让宠物持续说话或打断用户。

完成练习可解锁装饰、书桌植物或纪念贴纸；无付费抽奖，无饥饿、生病、死亡、断签惩罚。用户可以关闭奖励与宠物动画。宠物不分析用户情绪来施压，不表达排他依赖。

### 页面设计

| 页面 | 重点 |
|---|---|
| 今日书桌 | 宠物、简短问候、今日任务、三个练习入口、继续上次练习 |
| 练习空间 | 清楚的录音/发送按钮、对话、可折叠反馈、帮助与结束 |
| 心情日记 | 私密安静布局，角色与纠错时机选择，允许自由讲述 |
| 练习成果 | 原表达与进步对照、少量学习点、保存状态 |
| 成长花园 | 场景覆盖、能力变化、收藏表达与阶段成果 |
| 设置 | Vault、AI 服务、音频保留、角色偏好和宠物开关 |

Figma 交付计划：电脑/手机高保真页面、颜色与字体规范、组件与状态、宠物状态板、可点击原型。账号未连接时先完成设计说明和代码原型，不伪称已创建 Figma 文件。正式界面用真实组件实现，不交付一张截图当软件。

## 5. 教练体验

默认每次 15 分钟，支持 3–5 分钟低精力模式与更长练习。

教练以英文交流，必要时中文解释；每轮先回应内容，再给 1–2 项重点反馈，最后一个追问或复述任务。区分语法错误、表达优化和沟通建议，不把正确句子误判为错误。

提示依次为关键词、结构、句子开头、完整示范；记录提示水平。自然表达提供当前可复述版与可选进阶版，不改变事实、数字、承诺或感受。

练习模式即时反馈；连续模拟与雅思模考延后反馈。结束后总结优点、重点问题、最多三项学习资产与下次目标。实际保存成功后才显示“已保存”。

## 6. 职场与雅思模块

职场包括项目汇报、AI 项目介绍、领导沟通、会议讨论、供应商沟通、工作总结。首批 30 张人工审阅场景卡，以沟通任务而非固定句子为完成标准。

支持连续剧情，例如供应商资料审核 Agent 从需求、立项、接口对接到试点总结。事实表保持稳定，追问根据回答调整。

雅思第一阶段覆盖口语 Part 1/2/3，后续完整模考；听力、阅读、写作专项是扩展范围。文字不能评估真实流利度或发音，不输出虚构总分。参考反馈附实际证据，不能冒充官方评分。

## 7. 心情日记模块

可选沟通风格：温暖朋友（默认）、反思导师、英语教练。角色是 AI 的风格，不是真人身份或专业心理资质。用户可说“不要建议，只听我说”“最后再纠错”“中文解释一下”。

默认先交流两三个回合，再提供少量英语反馈。允许中英文混合，帮助用户逐渐用英语描述感受。尊重用户说自己敏感，不建立心理诊断，不强迫正向结尾或追问私人细节。

保存原回答、对话、保持本人语气的英文成稿、语法/造句建议与可选反思。日记原文不被改写替换；正文默认不被检索到职场场景中。语言卡去除私人背景，用户可选择不提炼。

用户说“这一段不要记”时不保存该段或衍生学习卡；可选只保存成稿。不得承诺删除无法控制的第三方记录。日记与真实录音不进入 GitHub 或演示原型。

## 8. 语音与发音

应用链路：录音 → ASR 转写 → 用户修订 → 教练回应 → 可选语音播放。语音原文与转写修订分开保存。

发音专项链路：真实短句音频 → 经验证的音频评估 → 具体单词/重音/节奏建议 → 示范 → 重读比较。语音聊天不自动等于专业发音评分。

仅有文字时只提供读法建议，发音显示未评估。可取得音频时提供证据与不确定性；低置信结果请用户重读。重点是可理解性，不要求消除中国口音。

手机浏览器录音权限、HTTPS、网络、语音服务可达性、宿主原音频访问均在早期验证，服务与费用不预设未经核实结论。

## 9. Obsidian 与数据可靠性

```text
<Vault>/EnglishCoach/
  Home.md
  Profile.md
  Sessions/YYYY/MM/
  Journal/YYYY/MM/
  Mistakes/
  Expressions/
  Templates/
  Reviews/
  Weekly/
  Scenarios/
  Companion.md
  Attachments/                 # 可选录音
```

所有学习文本、复习状态、宠物成长状态均存 Markdown/YAML。录音是可选附件。应用配置与密钥不属于知识库；缓存可从 Markdown 重建，不另建永久学习数据库。

记录 ID、来源、输入类型、提示水平、来源轮次和完整度。时间按 Asia/Shanghai。会话状态为 in_progress、summary_pending、completed，完整度 complete/partial 单独记录。

逐轮检查点、临时文件替换、重试幂等、写后读回、人工编辑冲突保护。中断可恢复；结束总结失败不丢已保存内容。关闭界面不等于成功归档。

只访问专用 EnglishCoach 目录，不改 .obsidian 配置。Vault 不可写时保存临时待归档 Markdown，显示未归档，恢复后同步；临时内容不是第二知识库。

第一版由一台电脑负责最终写入。手机通过受控入口请求该电脑后端，不能直接读取 D 盘。离线与并发修改需明确状态，OneDrive 负责用户已有文件同步，不代替应用连接。

## 10. 复习与成长

每日最多新增三项：错误模式、表达卡、任务模板。复习每天最多三项或三分钟，防止积压。先采用透明间隔，后续可接 py-fsrs；算法只调度日期，不判断英语能力。

分别记录回忆结果与表达质量，独立使用和跨场景迁移才作为掌握证据。每四周做同类任务比较，展示具体变化，提示依赖下降比累计时长更有意义。

不默认公开排名、断签惩罚或强制提醒。宠物奖励来自完成任务，不来自日记情绪或虚构成绩。

## 11. 技术与版本管理

建议 React + TypeScript 响应式前端，Python + FastAPI 本地后端，Markdown/YAML 文件存储；轻量动画可用 SVG/CSS，精细资源后续扩展。具体 AI/ASR/TTS/发音服务在质量、连通性、费用实测后确定。宿主 UI 路线仅在验证后替代独立接口。

Codex 负责开发、测试和维护；应用后端负责参数校验、文件动作与恢复。文件动作与语言判断分开，路径限制在配置目录。

## 12. 交付顺序与验收
